## 2. Logic Chain

1. **From Observation 1 & 2**: The codebase currently relies on hand-written shadow modules (`models.py`, `parser.py`, `render.py`) for 11 diagram types, which duplicates AST model definitions, enum definitions, transformer registration, and render functions that should ideally precipitate directly from RDF ontology facts.
2. **From Observation 3 & 4**: 4 diagram types (`block`, `kanban`, `timeline`, `xychart`) are isolated in `src/mmdio/engine/types/`, while 5 diagram types (`kanban`, `timeline`, `block`, `pie`, `sankey`) have RDF facts in `packs/mmdio-pack/ontology.ttl` that drive generation into `src/mmdio/engine/_generated_*.py`.
3. **From Observation 2, 3, & 4**: The circular imports across `models.py` -> `_generated_models.py` -> `types/*_models.py` and `parser.py` -> `_generated_parser_registry.py` exist solely because generated code lands in `_generated_*` files while hand-written code lives in `models.py`, `parser.py`, `render.py`, and `types/`.
4. **From Observation 5 & 6**: The `ggen` pipeline and all 10 SPARQL gates are fully operational. Moving models, enums, parser registries, and render dispatchers to precipitate cleanly into first-class files directly under `src/mmdio/engine/` (removing the `_generated_*` prefix and `types/` subfolder) will satisfy R1 and R2 without breaking the test harness or gate validation.

## 3. Caveats

1. **Mindmap Recursion Gap**: As noted in `ontology.ttl:583-598`, `MindmapNode` is self-referential (`children: List["MindmapNode"]`) and rendered recursively. Tera templates currently unroll list fields to a fixed nesting depth of 2 (`_r1`/`_r2`), so Mindmap models/renderers cannot be fully auto-generated by the current templates without extending Tera templates to handle recursive ref fields.
2. **Sankey & Block Render Edge Cases**: Block connection labels (conditional output formatting) and Sankey flow string escaping (comma stripping) are handled in hand-written code; standard template rendering handles the basic structural output.

---

## 4. Conclusion

The mmdio codebase has a clean structure but suffers from three-way shadow fragmentation across shared hand-written modules (`models.py`, `parser.py`, `render.py`), type-scoped modules (`engine/types/*`), and derived files (`_generated_*.py`).

To achieve the target end-to-end architecture (A = μ(O)):
1. Expand `packs/mmdio-pack/ontology.ttl` facts to cover all supported diagram types.
2. Update `pack.toml` / templates to target first-class Python modules in `src/mmdio/engine/` (`models.py`, `enums.py`, `parser_registry.py`, `render_dispatch.py`, `fixtures.py`, `schemas.py`, `supported.py`).
3. Remove the redundant `_generated_*` files and `src/mmdio/engine/types/` directory once all AST models, token enums, parser registries, and render dispatchers are precipitated cleanly.
