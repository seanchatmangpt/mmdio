## 2. Logic Chain

1. **Root Cause Component A (Ontology Render Format Syntax)**:
   In `ontology.ttl` line 1248, `mer:Field_XYChartDiagram_series` defines `mer:fieldRenderFormat` as `"  {_r1.series_type}: [{_r1.values}]"`.
   - The colon `:` after `{_r1.series_type}` causes the Mermaid parser to throw `PARSE_ERROR ... got 'COLON'`. Valid `xychart-beta` syntax is `line [10, 20, 30]` without a colon.
   - The outer brackets `[{_r1.values}]` wrap the Python list representation `str(_r1.values)`. For `_r1.values = []`, `str([])` returns `"[]"`, producing `[[]]`.

2. **Root Cause Component B (Unpopulated Primitive List Field in Fixture Generator)**:
   In `generated_fixtures.py.tmpl`, when constructing nested model instances inside top-level list fields (`series=[DataSeries(...)]`), the template iterates over element fields (`ef`).
   - The template only checks `scalar-required`, `scalar-optional`, and `enum` kinds.
   - Primitive list fields on element models (such as `DataSeries.values` of type `float | str`) are omitted, causing `DataSeries.values` to default to `[]`.
   - Mermaid `xychart-beta` parser rejects `line []` with `Expecting NUMBER_WITH_DECIMAL, got SQUARE_BRACES_END`. A valid series requires non-empty numeric data (e.g. `[10, 20, 30]`).

3. **Synergy of Fix**:
   - Correcting `mer:fieldRenderFormat` in `ontology.ttl` to `"  {_r1.series_type} {_r1.values}"` removes the invalid colon and redundant outer brackets.
   - Setting `mer:fieldExampleValue "[10, 20, 30]"` for `mer:Field_DataSeries_values` in `ontology.ttl` and updating `generated_fixtures.py.tmpl` to emit primitive list fields on nested element models (`ef.fieldKind == "list" and ef.fieldExampleValue`) results in `example_xychart()` returning `DataSeries(series_type="line", values=[10, 20, 30])`.
   - `render_xychart` then emits `xychart-beta\n  line [10, 20, 30]`, which passes the Node Mermaid 11.16.0 oracle validation with exit code 0.

## 4. Conclusion

The failure of `TestOracleXYChartDiagram.test_xychart_generated` is caused by a dual flaw in `packs/mmdio-pack/ontology.ttl` and `packs/mmdio-pack/templates/generated_fixtures.py.tmpl`.

### Exact Fix Strategy

1. **`packs/mmdio-pack/ontology.ttl` Modifications**:
   - **Fix `mer:Field_XYChartDiagram_series` render format (line 1248)**:
     ```turtle

     mer:fieldRenderFormat "  {_r1.series_type}: [{_r1.values}]" ;
     # To:
     mer:fieldRenderFormat "  {_r1.series_type} {_r1.values}" ;
     ```
   - **Add example value for `mer:Field_DataSeries_values` (line 1312)**:
     ```turtle
     # Change:
     mer:fieldExampleValue "" .
     # To:
     mer:fieldExampleValue "[10, 20, 30]" .
     ```

   - **Support list-kind primitive element fields in fixture generation (lines 74 & 85)**:
     Inside both list and nested-ref element loops (`element_fields`), add a branch for list-kind fields with example values:
