## 2. Logic Chain

1. **Observation 1.1**: In Iteration 1, Worker 1 populated `mer:pythonSupport true` for all 15 diagram types in `packs/mmdio-pack/ontology.ttl` to pass SPARQL Law Gate `010_python_support_complete.rq`, but only added `mer:hasModel` RDF triples for 5 diagram types (`block`, `kanban`, `pie`, `sankey`, `timeline`).
2. **Observation 1.1**: `generated_models.py.tmpl` contains two queries with conflicting selection criteria:
   - `models`: Queries `?type mer:hasModel ?model . ?model a mer:PythonModel`. Returns 5 model classes.
   - `union_models`: Queries `?type mer:pythonSupport true`. Returns 15 model class names.
3. **Observation 1.1 & 1.2**: When `ggen sync run` executes:
   - `src/mmdio/engine/models.py` only defines 5 class models (`BlockDiagram`, `KanbanDiagram`, `PieChart`, `SankeyDiagram`, `TimelineDiagram`).
   - `models.py` ends with `MermaidDiagram = ( BlockDiagram | C4Diagram | ClassDiagram | ... )` referencing 10 undefined model classes.
4. **Observation 1.2**: Executing `import mmdio.engine.models` raises `NameError: name 'C4Diagram' is not defined` at line 216 of `models.py` because `C4Diagram` was never declared.
5. **Observation 1.1 & 1.2**: `generated_render_dispatch.py.tmpl` similarly queries `?type mer:pythonSupport true`, generating import statements for undefined classes (`C4Diagram`) and undefined render functions (`render_c4`), causing cascading `ImportError` exceptions across `src/mmdio/engine/__init__.py` and the `pytest` test suite.
6. **Conclusion & Remediation**:
   - To achieve query consistency and defense-in-depth, the SPARQL queries in `generated_models.py.tmpl` (`union_models`) and `generated_render_dispatch.py.tmpl` (`rows`) MUST be updated to join `mer:hasModel ?model . ?model a mer:PythonModel ; mer:isTopLevel true .`.
   - In addition, merging all RDF triples from `EXPANSION_RDF_SNIPPETS.md` into `packs/mmdio-pack/ontology.ttl` will provide the missing `mer:hasModel` facts for all 10 remaining diagram types, allowing all 15 diagram models and render dispatchers to precipitate cleanly.

## 4. Conclusion & Concrete Strategy

### 4.1 Root Cause Summary

The `union_models` query in `generated_models.py.tmpl` and `rows` query in `generated_render_dispatch.py.tmpl` filtered diagram types solely by `mer:pythonSupport true` rather than verifying that corresponding model definitions (`mer:hasModel ?model . ?model a mer:PythonModel ; mer:isTopLevel true`) exist in `ontology.ttl`. This caused `models.py` and `render_dispatch.py` to reference 10 undefined class names and render functions, crashing Python import evaluation with `NameError: name 'C4Diagram' is not defined`.

### 4.2 Template Query Fix Strategy

To fix this issue permanently and ensure clean compilation under both complete and partial ontology states:

#### 1. Update `union_models` in `packs/mmdio-pack/templates/generated_models.py.tmpl`:

```sparql
  union_models: |
    PREFIX mer: <https://seanchatmangpt.github.io/ontology/mermaid#>
    SELECT ?internalId ?modelModule ?modelClass WHERE {
      ?type a mer:DiagramType ;
            mer:pythonInternalId ?internalId ;
            mer:pythonSupport true ;
            mer:hasModel ?model ;
            mer:pythonModelModule ?modelModule ;
            mer:pythonModelClass ?modelClass .
      ?model a mer:PythonModel ;
             mer:isTopLevel true .
    } ORDER BY ?internalId
```

#### 2. Update `rows` in `packs/mmdio-pack/templates/generated_render_dispatch.py.tmpl`:

```sparql
  rows: |
    PREFIX mer: <https://seanchatmangpt.github.io/ontology/mermaid#>
    SELECT ?internalId ?modelModule ?modelClass ?renderModule ?renderFunction WHERE {
      ?type a mer:DiagramType ;
            mer:pythonInternalId ?internalId ;
            mer:pythonSupport true ;
            mer:hasModel ?model ;
            mer:pythonModelModule ?modelModule ;
            mer:pythonModelClass ?modelClass ;
            mer:pythonRenderModule ?renderModule ;
            mer:pythonRenderFunction ?renderFunction .
      ?model a mer:PythonModel ;
             mer:isTopLevel true .
    } ORDER BY ?internalId
```

#### 3. Merge `EXPANSION_RDF_SNIPPETS.md` into `packs/mmdio-pack/ontology.ttl`:

Worker 2 must merge all RDF triples from `EXPANSION_RDF_SNIPPETS.md` into `ontology.ttl` so that all 15 diagram types carry `mer:hasModel` facts, precipitating full Pydantic models for all 15 diagram types.
